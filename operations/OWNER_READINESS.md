# Before the first booking

Prepared October 18, 2026. This is a short completion list for actual evidence,
not a declaration that the business is ready to accept every service.

1. **Available dates.** Start with `capacity-draft-2026-10-19.json`. Confirm real
   outside obligations, holiday/absence dates, review windows and the correction
   tail, then transfer the accepted dates into `capacity-worksheet.json` and the
   existing job record. The draft reserves at most 20 planned client hours/week
   and relies on no weekend work. Accept one build start at a time until one full
   delivery supplies observed stage times. Record actual writing, design, build,
   review, launch, handoff and correction time in that job's existing receipt.
   Reconcile overruns and unused time before accepting the next start.

2. **Stripe and cash.** The October 18 API reports charges and payouts enabled.
   The owner Dashboard separately confirms an active “Provide a tax ID for
   Wonder and Method” task. Payouts will pause on November 15, 2026 or when
   volume reaches $600.00. Complete that task using the actual business details
   and requested evidence; record the resolved status and date privately. The
   Dashboard displayed a $0.00 balance. Do not treat enabled payouts or pending
   payouts as funded reserves. The existing cash/acceptance gate remains in force.

3. **Annual service.** Keep annual enrollment on hold until the actual funded
   gross unearned balance, separate fee buffer and accepted undelivered work are
   recorded. Use the structured fields in `templates/billing.json`. The local
   settlement calculator has pre-start and four-cycle tests; a completed Stripe
   sandbox refund route still needs its own dated provider evidence. Record the
   effective date, ten-business-day initiation deadline, owner and undisputed
   amount. Do not infer actual funds from a successful calculation.

4. **Recovery without this Windows profile.** From a separate owner-controlled
   device or clean profile, demonstrate access to the private source backup,
   hosting/Cloudflare, Stripe, domain/DNS and the Gmail/Fastmail mailboxes. Use
   existing secure recovery methods; never put recovery codes or credentials in
   this repository. Confirm a second factor and recovery contact still work.
   Record successful access and missing steps in a private dated checklist.
   The local synthetic database rehearsal proves an isolated restore and
   reconciliation; it does not prove independent provider or mailbox recovery.
   Restore only into a fresh isolated database, compare references and frozen
   notification state, and reconcile newer production records before any
   separately authorized recovery action. Never replace production with an old
   export just because that export opens successfully.

5. **Daily reply routine.** At business-day opening and closing, run the
   aggregate logger and separately review mailbox, chat and outstanding replies
   as described in `INQUIRY_HEALTH.md`. Retain completion and incident references
   for an actual operating period. Before any absence, arrange real coverage or
   update the public response window and contact affected clients through their
   agreed channels. No continuous staffing or independent alert is established
   by the website code.

Use `node scripts/capacity-calendar.mjs operations/capacity-worksheet.json` and
the existing release/readiness checks. A technical website release does not
remove these business gates. Keep unresolved inputs visible until completed.
